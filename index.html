How I build

The same few rules show up in every project above. They are in the code and the tests, not just in the README.

  • The model proposes, a person approves.Models read, summarize and suggest. Anything that writes to the books or the calendar needs an explicit yes, bound to exactly what was shown.
  • Least privilege by construction.Roles decide which tools exist for a caller, so a tool that was never registered cannot be called by mistake, or by a model that was talked into it.
  • Tested without the network.Dependencies are injectable, so tests run with no secrets and no live services, including hostile inputs such as forged signatures and prompt injection.
  • Honest limits.Each public repo ends with a list of what it does not do, such as single-instance state and unmeasured model accuracy, so nobody has to find out the hard way.
